4 — Scheduler: rule-based engine (exact logic to implement)

Implement scheduler as a deterministic function you can unit test. Core responsibilities:

Inputs:

All active goals for user (with due_date, priority, remaining_minutes)

User availability windows and weekly commitments/busy slots

Existing scheduled work_units (so you don't double-book)

Configurable rules (preserve minimum daily minutes for long goals, maximum chunk size, etc.)

Process (step-by-step algorithm):

Compute horizon: find all days between today and the nearest due_date of active goals (or configurable horizon, e.g., 30 days).

Create availability calendar: for each day, map free time slots by subtracting weekly commitments and existing calendar events.

Normalize goal urgency score: for each goal compute urgency = f(priority, time_left, remaining_minutes) where:

time_left = minutes until due_date (tz-aware)

urgency ∝ (priority_weight / (time_left / remaining_minutes + ϵ))

This gives higher score for high-priority and close-deadline goals.

Chunking:

For each goal, split remaining_minutes into work units of size between min_chunk and max_chunk (configurable, e.g., 25–90 minutes), preferring Pomodoro-like sizes.

Respect prerequisites: do not schedule units of a goal whose prerequisite is incomplete.

Greedy allocation by day:

Iterate days in chronological order.

On each day, allocate slots from highest urgency to lowest until day capacity exhausted.

Prefer to place earlier in the availability window (avoid backloading).

Preserve min_daily_progress for long-range goals: ensure each long goal gets at least X minutes per week/day if configured.

Hard constraints & overflow handling:

If a goal cannot be scheduled before its due date given available windows → mark as conflict and return to client with suggested actions (extend due date, increase availability).

Output:

A set of work_units with scheduled_start/end and status todo.

Audit log of why particular units were scheduled (for UI tooltips).

Rescheduling logic (on skip / completion / new goal):

When a unit is skipped or a new goal is added, re-run scheduler for remaining horizon with existing done units immutable and skipped units marked as available for reallocation (but with a small penalty to avoid immediate rescheduling to same later day).

Add an urgency escalation for overdue units: escalate urgency linearly by days overdue to prevent infinite postponement.

If user reduces availability, recompute and mark conflicts.

Determinism & Testing:

The scheduler must be deterministic given the same inputs and configuration.

Expose deterministic seed or deterministic ordering for unit tests.

6 — Task lifecycle & actions (exact behaviors)

start action:

Marks work_unit in-progress and optionally starts a timer in UI.

done action:

Marks status = done, decrement remaining_minutes on goal, remove from future schedule or mark as completed.

Trigger rescheduler to fill freed time with other work_units if desired.

skip action:

Marks status = skipped, timestamp it, re-run scheduler and escalate urgency for the skipped unit.

edit/reschedule action:

Manual move updates scheduled_start/end and persists; triggers a light scheduler pass to adjust surrounding units.

Overdue handling:

If current time > scheduled_end and status not done → status becomes overdue, escalate urgency and surface in dashboard.

Use cases (exact, real user flows)

Daily study plan for exams (student)

Student creates 3 goals (Math midterm due in 7 days, Physics assignment due in 3 days, Long-term project due in 30 days). Sets availability 18:00-21:00. Scheduler chunks and prioritizes physics and math first; long-term project gets a minimum daily chunk.

Catch-up after missed sessions

Student skips two sessions. Scheduler re-runs, escalates overdue units’ urgency, redistributes remaining time to ensure the closest deadlines are fulfilled first.

Parent / Mentor check-in

Parent logs into mentor view and sees next 7 days, upcoming deadlines, and a progress percentage for each goal.

Busy week with constraints

User marks three evenings busy. Scheduler respects reduced availability, flags a conflict for a near-term high-effort goal and suggests actions (extend deadline or add study hours).

Add last-minute high-priority task

User creates a new urgent goal. Scheduler reorders upcoming days to allocate time to the urgent goal and warns about likely impact to long-range goals.

Export / Reminders

User requests browser reminders 15 minutes prior to each session. Notifications fire; missed notifications can be checked in app logs.
